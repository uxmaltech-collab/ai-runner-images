# Preserve reproducible work before cleaning a Tart build host

Inventory the commissioning workspace and installed service separately. Source
promotion, source-pin adoption, installed runtime, image distribution and tested
restoration are different results. A stopped VM, clean Git checkout or checksum
list does not establish that its contents can be discarded.

## Establish canonical source coverage

Read the latest receipts and the actual remote branch. Earlier checkpoint prose
may still describe a completed PR as pending. Confirm merge commits and receiver
readback; preserve older receipts unchanged and add a current index.

| Reusable knowledge | Canonical source |
| --- | --- |
| Native layer construction, SwiftLint, combined engines, Flutter/Dart, deadlines and disposable qualification | This repository's `scripts/build-images.py`, `scripts/tart-layer.py` and `recipes/` |
| Host installer, dedicated keychain, guest/session/RPC, admission, cancellation and collection | `uxmaltech-collab/ai-templates-resources`, `sre/github-runners-host-sre` and `runners/control-plane` |
| Original findings, failed attempts and repair ancestry | `docs/research/2026-09-16`, `docs/recovery.md`, provenance and qualification records |
| Organization onboarding and real canary worksheets | Templates `docs/collab-e2e-prompts/`; bind each new organization's own inputs |
| Host identities, authority, application environment and business flows | Their declared consumer/host/application owners |

List real repositories separately from Git repositories generated by tests.
Capture HEAD, branches, tracked changes and untracked paths. For a rebased branch,
ancestry alone is insufficient: compare stable patch IDs with canonical history.
Retain dirty worktrees and unmatched commits until their source is published or
their disposition is established. Never merge an obsolete prototype solely to
make its commit reachable.

## Protect reconstruction inputs and active state

Retain the declared pristine/neutral parent, current accepted images and every
local-only artifact needed by a recipe or recovery reference. Keep config, disk,
NVRAM, manifest, source commit and physical ancestry separately. Neither an image
alias nor an OCI-shaped local reference proves remote availability.

Also retain licensed Apple inputs, pinned public tool archives and their hashes
when they are the only verified build inputs. The native backend currently starts
at a measured accountless macOS/Xcode parent. It does not prove a clean-machine
Apple installation or recover a deleted parent from Git.

Observe active jobs, cleanup/quarantine, VM processes, mounts and open holders.
Do not remove installed executables, launchd services, keychains, account homes,
job ledgers or service state as commissioning clutter. A manual builder shares
the physical host's capacity with the executor. Scope housekeeping to positively
identified retired data; stopped state alone is not ownership or deletion proof.

## Retire generated work with a verifiable record

1. Create an explicit path allowlist for historical pytest workspaces, bytecode
   and caches. Exclude source worktrees, private receipts, image tuples, tool
   inputs and installed service dependencies. Avoid age-only or host-wide globs.
2. Preserve diagnostic test workspaces in a private archive when they contain
   the only failure reproduction. Record each member's path, type, link target,
   size, mode and content hash. Preserve links without following them.
3. Read the completed archive and verify the manifest against every member.
   Check live paths have not changed before removal. Keep the archive outside the
   deletion set, with restricted access. A local archive is local retention, not
   an off-host backup.
4. Remove only the verified allowlist. Preserve logs, JUnit and original source
   checkpoints, and write a receipt of actual removals and failures.
5. Recheck the installed configuration, service, active jobs and retained image
   metadata. Report logical bytes separately from observed free space: APFS
   clones and snapshots make directory totals poor estimates of reclaimed space.

Keep raw transcripts and customer bindings out of shared Git. Publish neutral
procedures, source corrections, reproducible fixtures and sanitized results in
their owning repositories. Keep private originals under the operator's retention
policy. A source review candidate and a retained local image must remain labeled
as such in the cleanup result.

## Capacity and APFS quota lessons

Capacity is constrained by the shared controller/host limit, CPU, RAM and the
smaller of filesystem free space and volume quota minus use. Manual builders
consume the same physical slots. Reserve headroom for host services and account
for the full writable VM budget, not only the parent's current allocated blocks.

Before a capacity change, obtain a fresh controller admission hold with zero
active leases and preserved queued work. Reconcile native jobs, quarantine and
VMs before stopping the owned executor. Preserve the accepted guest sources and
image bindings when applying a controller-only capacity release. Validate the
keychain/RPC service as its actual account, then obtain the controller's real
adoption and admission-restoration receipt. Configuring two slots does not prove
two simultaneous complete application builds.

A local fixture on macOS 26.6.2 build 25G83 observed the private system function
`APFSVolumeUpdateBounds` with signature
`int(const char *bsd_volume, uint64_t reserve_bytes, uint64_t quota_bytes)`.
The fixture verified setting/increasing an existing volume's quota, unchanged
volume UUID/reserve/sentinel bytes, persistence after detach/reattach and final
attachment absence. Its initial failed `addVolume` attempt was retained. This is
an observed implementation detail, not a supported cross-version API or a new
production adapter. Requalify it on an exclusive disposable fixture after an OS
change; preserve failures and use the host owner's reviewed operation for actual
storage changes. Never replay the original host-bound checkpoint helper elsewhere.

Future image-adoption operations must read the currently authorized quota rather
than assert the quota from the first provisioning receipt. Keep that historical
receipt intact. Templates PR269 owns shared capacity adoption; the private native
quota operation remains host-specific. SSH service-ACL membership is likewise an
explicit host prerequisite until its installer owner implements that operation;
see Templates `sre/github-runners-host-sre/OPERATING-LESSONS.md`.
