# Native backend review verification

PR6's six review comments are addressed in the native recipes and their existing owners. The fixes derive staging and installation envelopes from the payload and selected recipes, remove the build/qualification import cycle, move guest programs and session policy into ordinary files, reuse installer launcher/layout definitions, flatten component results, and cover qualification failures and cleanup in dedicated regressions.

A real `macos-flutter` build at `13f30a632bda9ee6c450070c21a8b7128a46af59` started from the preserved neutral macOS/Xcode parent. It transferred and verified the complete 2,904,514,560-byte payload, freshly installed SwiftLint, all three engines and Flutter/Dart, then normally stopped and sealed the image. Its disposable clone completed preparation, shutdown, another boot, Aqua readiness and real SwiftLint as UID502/GID20 without admin membership. The valid fixture passed; the deliberate force-cast fixture produced the required JUnit violation.

That execution exposed a competing-lock bug in the new owner deletion operation. The host held `config.json` while the Tart subprocess needed its own lock, causing Tart to report the existing stopped VM as absent. Commit `7e15a52` removes the competing host lock while retaining the stopped-state and open-holder checks and the declared execution context. A child-process lock regression and the qualification suite passed (11 tests); the same stopped qualification VM was then deleted successfully through the corrected owner. Its receipt and parent metadata prove child absence and preservation. No installation or qualification step was repeated.

The original front-end exit1 and `cleanup-unconfirmed` receipt remain unchanged. The separate native reconciliation receipt closes that cleanup failure; it does not retroactively turn the original command into exit0. The initial 49 focused tests passed on Darwin. An earlier pytest collection collision is retained privately and resolved by using `--import-mode=importlib` for recipes with matching test filenames.

`summary.json` separates installed image source, cleanup correction, physical parent and final image tuple. The images remain local and unadmitted. Existing Xcode, Simulator, Maestro and application qualification evidence is reused; no new application canary, authenticated agent session or remote restore is claimed. Private logs, exact commands, original failures and the reconciliation are delivered through host-exchange.
